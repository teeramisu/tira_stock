# 预测真值系统设计方案

## 核心哲学

> **预测不是为了准确，而是为了赚钱。**
> 一个 +0.1% MAE 的模型如果总是在错误的方向上加仓，比一个 +2% MAE 但方向正确的模型更危险。

所以我们不构建"准确率"指标，而是构建**对齐交易损益的奖励函数**。

---

## 一、真值标签体系

### 1.1 多层次标签

传统做法是单一未来收益，但这是信息浪费。对每个日期 T，构建多层标签：

```
日期 T
  │
  ├─ H=5   收益  │  方向  │  Regime  │  波动率  │  尾部风险
  ├─ H=10  收益  │  方向  │  Regime  │  波动率  │  尾部风险
  ├─ H=21  收益  │  方向  │  Regime  │  波动率  │  尾部风险  ← 月
  ├─ H=63  收益  │  方向  │  Regime  │  波动率  │  尾部风险  ← 季
  └─ H=252 收益  │  方向  │  Regime  │  波动率  │  尾部风险  ← 年
```

每个 H 输出 5 个真值，共 5×5=25 个标签。

### 1.2 Regime 定义（软边界）

不用硬阈值 ±5%，用 sigmoid 软化边界，使梯度可导：

```
P(BULL)   = sigmoid((return - 0.03) / 0.01)    # 收益 > 3% 可能是 BULL
P(CRASH)  = sigmoid((-return - 0.07) / 0.02)    # 收益 < -7% 可能是 CRASH
P(BEAR)   = sigmoid((-return - 0.03) / 0.01) - P(CRASH)
P(RANGE)  = 1 - P(BULL) - P(BEAR) - P(CRASH)
```

这样 +4.9% 的收益不是"一刀切 RANGE"，而是 85% BULL + 15% RANGE。

### 1.3 拐点标签

不仅要预测"未来 20 天是什么 Regime"，还要预测**什么时候变**：

```
turning_point_horizon = min { k > 0 | regime(T+k) ≠ regime(T) }
```

如果 T+15 天时 Regime 从 BULL 变成 BEAR，则：
- `turning_point = 15`（距离拐点还有 15 天）
- `turning_intensity = |return_before - return_after|`（拐点强度）

这个标签用 survival analysis 建模，输出"未来每个时间步拐点的概率"。

## 二、奖励函数（Reward Design）

### 2.1 核心原则

| 原则 | 含义 |
|------|------|
| **方向 > 幅度** | 猜对涨跌比猜对具体数值更重要 |
| **尾部 > 日常** | 预测对一次 CRASH 抵得上 100 次 RANGE |
| **近期 > 远期** | 近 3 个月的预测比 3 年前的权重高 10 倍 |
| **可操作性 > 统计显著性** | 一个能产生正 P&L 的 40% 胜率信号，好于 55% 胜率但无法交易的信号 |

### 2.2 分层奖励

```
Total Reward = w1 * R_direction + w2 * R_magnitude + w3 * R_regime + w4 * R_calibration
```

**R_direction（方向奖励）**：
```
如果 sign(预测) == sign(实际):
    奖励 = |实际收益| * 杠杆倍数
否则:
    惩罚 = -|实际收益| * 杠杆倍数 * 0.5
```

关键：奖励和实际波动幅度成正比。预测对一次大涨(+8%)比预测对一次小涨(+1%)得到更多奖励。这迫使模型关注大行情。

**R_magnitude（幅度奖励）**：
```
R_magnitude = -|预测收益 - 实际收益| * exp(-|实际收益| * 5)
```

加了一个衰减项：实际收益越极端，幅度惩罚越小。即"大行情时方向优先，小行情时精度优先"。

**R_regime（Regime 奖励）**：
```
# 混淆矩阵加权：不同错误有不同代价
代价矩阵:
              预测 BULL  RANGE  BEAR  CRASH
实际 BULL        0      1      5     10
实际 RANGE       1      0      3      8
实际 BEAR        5      3      0      4
实际 CRASH      10      8      4      0

# 把 CRASH 预测成 BULL 的代价是 10（最严重）
# 把 BULL 预测成 RANGE 的代价是 1（最轻）
```

**R_calibration（校准奖励）**：
```
# 模型输出的 confidence 应该和实际准确率一致
# 对置信度分桶，计算每个桶内的实际准确率
# 奖励：-|桶内准确率 - 桶的置信度|
```

### 2.3 时间衰减

```
样本权重 = exp(-λ * (今天 - 样本日期).days)
```

λ = ln(2) / 90（半衰期 3 个月）。3 个月前的样本权重只有今天的一半。

### 2.4 事件加权（重要性采样）

某些日期比其他日期重要 100 倍：

| 事件 | 权重乘数 | 原因 |
|------|---------|------|
| 普通交易日 | 1x | |
| CRASH 日（收益 < -5%） | 10x | 尾部事件，稀缺 |
| 拐点日（regime 切换） | 8x | 战略价值高 |
| 财报季（CN: 4/8/10月） | 3x | 波动率放大 |
| 政策发布日 | 5x | 不可预测性高 |

## 三、多任务联合训练

### 3.1 任务分解

```
共享 Backbone (Transformer Encoder)
  ├── 收益预测头 (5 个 horizon × 3 个 quantile = 15 个输出)
  │     └── 输出: p5, p50, p95 (5%, 50%, 95% 分位数)
  ├── Regime 分类头 (4 类软标签)
  ├── 拐点预测头 (每个时间步的拐点概率)
  └── 波动率预测头 (未来 H 天的波动率)
```

### 3.2 损失函数

```
L_total = α₁ * L_quantile + α₂ * L_regime + α₃ * L_turning + α₄ * L_vol
         + β * L2_regularization

其中：
  L_quantile = Σ ρ_τ(y - ŷ_τ)   分位数损失，τ ∈ {0.05, 0.50, 0.95}
  L_regime   = 加权交叉熵（代价矩阵加权）
  L_turning  = 二元交叉熵（每个时间步）
  L_vol      = MSE(log σ_pred, log σ_actual)
```

权重 α 不是固定的，而是在验证集上通过**贝叶斯优化**搜索得到。

### 3.3 分位数损失

```
ρ_τ(u) = u * (τ - I(u < 0))

其中 u = y - ŷ_τ，I 是指示函数

τ=0.50 → MAE（预测中位数）
τ=0.05 → 下界分位数（乐观情景）
τ=0.95 → 上界分位数（悲观情景）
```

分位数损失的输出可以直接用来做**风险预算**——比如只在下界 > 0 时才做多。

## 四、评估框架

### 4.1 累积 P&L 曲线

不是看 MAE，而是模拟交易：
```
每天 T，如果模型预测 T+5 收益 > 0 → 做多
如果预测 < 0 → 做空（或空仓）
仓位大小 = 置信度（1 - 分位数宽度）

累计收益曲线 → 夏普比率 → 这才是真正的评估指标
```

### 4.2 分层回测

按 Regime 分层评估：

| 子集 | 样本数 | 方向准确率 | 累计P&L | 最大回撤 |
|------|--------|-----------|---------|---------|
| 全量 | 1000 | 55% | +12% | -8% |
| BULL 期间 | 400 | 65% | +18% | -3% |
| BEAR 期间 | 200 | 45% | -5% | -8% |
| CRASH 期间 | 50 | 80% | +8% | -2% |
| RANGE 期间 | 350 | 48% | -3% | -4% |

CRASH 期间 80% 准确率但只有 50 个样本 → 这个模型在尾部事件上表现好，但需要在更多数据上验证。

### 4.3 对抗验证

```
训练一个分类器区分"训练集"和"验证集"
如果分类器能轻易分开 → 存在数据泄露
如果 Auc > 0.7 → 有泄露，需要重新切分
```
