# Playbook · refactor（行为不变，只改结构）

> 适用：抽函数、拆模块、改名、消除重复。
> 铁律：**行为不变**。任何行为变化都要拆成 feature 或 bugfix。

## 步骤

1. **定义「不变」的边界**
   - 哪些函数签名、返回结构、HTTP 响应字段必须保持一致
   - 写下来，作为后续核对清单

2. **确认现有测试覆盖**
   ```bash
   pytest <相关测试> -q
   ```
   - 覆盖不足时**先补测试**（纯新增，不需要人工放行），再重构
   - 判据：重构前这些测试全绿

3. **小步改**
   - 一步只做一种变换（先抽取、再改名、再移动文件）
   - 每步之后跑一次相关测试，不要攒到最后

4. **跑全量**
   ```bash
   scripts/ci/verify.sh --full
   ```
   - 覆盖率不得下降（ratchet 会拦）
   - 若覆盖率下降，说明有分支没跑到 —— 补测试或确认死代码

5. **检查文档是否过期**
   - 改了函数名/模块路径 → 更新 `README.md` 或 `docs/`

6. **开 PR**
   - 标题 `refactor(<scope>): <描述>`
   - 描述里写明「行为不变的依据」（哪些测试覆盖了它）
   - 必须写 `## 回退`：revert 是否安全

## 完成判据

- [ ] 重构前后相关测试结果一致（数量与结论）
- [ ] 覆盖率未下降
- [ ] 没有混入行为变更
- [ ] 描述说明了「不变」的证据

## 常见失误

| 失误 | 后果 |
|---|---|
| 重构时「顺手」修个 bug | 无法判断回归来自哪一步 |
| 一次移动多个文件 + 改名 | diff 巨大，review 失效 |
| 依赖「反正有测试」而不看覆盖率 | 未覆盖分支的行为可能已变 |
