# Playbook · bugfix（现有行为错了）

> 适用：报错、结果不对、接口 500、数据缺失。
> 铁律：**先复现，再修**。没有失败用例的修复等于没修。

## 步骤

1. **拿到最小复现**
   - 直接从报错栈 / 用户描述反推：哪个输入、哪个函数、哪一行
   - 能一行 `python -c` 复现就一行，不要写脚本
   - 判据：命令**非 0 退出**，且错误信息与现象一致

2. **定位真因（不是症状）**
   - 读出错行的上下文，确认输入的类型/取值从哪来
   - 常见真因：类型未转换、缺省值、边界条件、并发共享状态
   - 判据：能说出「因为 X 传进来是 Y，所以 Z 崩了」

3. **写失败测试**
   - 放在对应模块的测试文件；断言「修复后应成立的行为」
   - 判据：不加修复时该测试**红**

4. **最小修复**
   - 只改真因所在处；不要顺手重命名/重排
   - 若同类问题在别处也存在，**记下来另开任务**，不要一起改

5. **验证**
   ```bash
   pytest <失败的测试> -q        # 先确认转绿
   scripts/ci/verify.sh --full   # 再跑全量
   ```

6. **写清影响面**
   - 这个 bug 影响哪些接口/用户可见行为
   - 是否需要补数据（历史脏数据要不要回刷）

7. **开 PR**
   - 标题 `fix(<scope>): <症状>`
   - 描述里必须贴「修复前 / 修复后」的命令与输出

## 完成判据

- [ ] 有「修复前失败」的记录（命令 + 输出）
- [ ] 新测试在修复前红、修复后绿
- [ ] 全量 `verify.sh --full` 绿
- [ ] 描述里说明了影响面

## 常见失误

| 失误 | 后果 |
|---|---|
| 直接改代码，没有复现 | 无法确认修的是真因 |
| 只加 `try/except` 吞掉异常 | 症状消失，问题潜伏 |
| 顺手把别处的同类问题一起改 | PR 范围超限，回滚牵连 |
| 用 `# type: ignore` / `noqa` 掩盖 | 门禁形同虚设 |
